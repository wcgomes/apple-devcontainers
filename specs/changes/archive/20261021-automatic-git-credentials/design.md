# Design: automatic-git-credentials

## Approach
Use the existing macOS executable for normal commands and an internal broker entry point, supervised by one per-user LaunchAgent. The same executable embeds two small static Linux variants of a C guest relay/client. Keep policy independent of launchd/process/runtime adapters. Observable guarantees and acceptance scenarios are in spec.md; this document explains implementation decisions, not additional guarantees.

The design overflow is real: supervision, cross-platform delivery, duplex framing, host-provider lifetime, migration, and isolated verification interact across process and trust boundaries. A detached up child avoids a job definition but supplies no automatic restart and creates orphan/discovery problems; launchd is the chosen tradeoff. No foreground mode, HTTP listener, new provider, package-manager guest installation, or new public flags are added.

## Significant decisions

### Guest delivery decision
The user approved bundling a static Linux helper and its necessary build/distribution work. Implement one small C source at `Guest/GitCredentialRelay/main.c`, with client get/store/erase and relay server modes. Use POSIX sockets, poll, bounded buffers, and no third-party application libraries. Store is consumed locally without persistence; erase/get cross the relay. A thin private POSIX-sh Git helper can exec this binary, retaining the existing product helper path/configuration contract. Python/socat/guest compilers are not prerequisites.

Build linux/arm64 and linux/amd64 using `zig cc -target aarch64-linux-musl` and `zig cc -target x86_64-linux-musl` respectively, with explicit static linkage, fixed optimization/target baseline, stripped symbols, disabled build IDs, normalized source paths, and no timestamps/random data in outputs. The host remains macOS arm64; two guest variants do not enable or install Rosetta. Select the guest variant from container machine JSON platform, never uname of the host. Unsupported or unparseable platforms fail credential setup using the contract's soft/explicit error distinction.

`scripts/bootstrap-guest-toolchain.sh` explicitly bootstraps Zig 0.15.2 into `.build/toolchains/zig-0.15.2/` when needed; it does not assume zig/LLD/a musl sysroot is already installed. For the macOS arm64 source/release host, download only `https://ziglang.org/download/0.15.2/zig-aarch64-macos-0.15.2.tar.xz`, verifying SHA-256 `3cc2bab367e185cdfb27501c4b30b1b0653c28d9f73df8dc91488e66ece5fa6b` before extraction/execution. A Linux x86-64 build-only CI job uses `https://ziglang.org/download/0.15.2/zig-x86_64-linux-0.15.2.tar.xz`, pinned to `02aa270f183da276e5b5920b1dac44a63f1a49e55050ebde3aecc9eb82f93239`. Verify a retained cached archive against the same pin before reuse; version text alone is not an integrity check. Toolchain download failure is a source-build error, never an excuse for runtime guest downloads. This is an explicit maintainer/source-build prerequisite, not a new end-user runtime dependency.

`scripts/build-guest-credential-relay.sh` compiles both raw artifacts using the bootstrapped compiler, then invokes a host Swift generator/verifier at `scripts/prepare-guest-credential-assets.swift`, using macOS Foundation/CryptoKit rather than assuming Python. Raw artifacts live at `.build/guest-credential-relay/linux-arm64/adevcontainer-git-relay` and `.build/guest-credential-relay/linux-amd64/adevcontainer-git-relay`. A deterministic manifest at `.build/guest-credential-relay/manifest.json` records target, protocol version, source/toolchain identity, size, and SHA-256. Parse ELF64 little-endian headers/program tables to verify the target machine (183 for AArch64, 62 for x86-64), bounds, and absence of an interpreter or dynamic-library dependencies. Rebuild in independent temporary output/cache directories and compare bytes/hashes; toolchain unavailability or nondeterminism blocks release. A build-script-only raw mode lets Linux CI compile the identical static outputs without requiring the macOS Swift/CryptoKit generator; it is not a new product flag or Linux host CLI port.

Generate gitignored `Sources/ADevContainerLib/Git/Generated/GuestGitCredentialEmbeddedAssets.swift` containing deterministic base64 payloads and the same manifest constants. SwiftPM's existing library target automatically compiles this Swift file: no resource bundle lookup or second installed executable is needed. Clean source/CI/release builds run the preparation script before `swift run adevcontainerTests` / `swift build`; document this deliberate source-build change in README and CONTRIBUTING. Generated source/binaries/toolchain archives are not committed. A package script `scripts/package-release.sh` packages the existing single host executable plus applicable third-party notices; Homebrew still installs that binary, and retains the notices as documentation. There is no runtime dependency on source paths, generated files, Zig, or companion resource bundles. Preserve the release tarball name/checksum conventions.

The artifact adapter verifies embedded hashes/ELF metadata before provisioning. Write the guest binary into a private temporary file with exec stdin, read it back via the existing runtime read-file boundary, and compare host-computed digest/length before atomic installation as 0700. Reject unsafe paths. Relay hello checks protocol/platform identity before any provider delivery; no runtime host fallback on wrong architecture. `scripts/test-guest-credential-relay.sh` runs native parser/socket tests on the macOS build host using the already-required CLT C compiler and executes the actual linux/amd64 static output on a Linux x86-64 CI runner using the pinned toolchain. linux/arm64 target execution is exercised in separately authorized throwaway Apple-container smoke, not assumed from a passing ELF check. The test-only native macOS executable is never shipped.

Evidence for the selected build mechanism: the official [Zig overview](https://ziglang.org/learn/overview/) documents C cross-compilation and bundled musl without a separate sysroot; the [download index](https://ziglang.org/download/index.json) supplied the fixed 0.15.2 archive/hash during planning. Zig was not installed locally when inspected. No download, native compilation, or target execution has been performed in this spec phase. Verify compiler flags/build reproducibility in the first implementation phase instead of claiming that architecture is already tested.

### Supervision and session lifecycle
Register a user-private LaunchAgent targeting a stable absolute path to the installed CLI, with an internal broker mode, no sudo, and a launchd restart policy. An advisory per-user lock plus idempotent bootstrap prevents competing registry owners. Commands communicate over a user-private host-local control socket with same-UID peer validation; that socket is never exposed to the guest. The production job/state are distinct from smoke contexts. Job registration checks the resolved executable path so a later lifecycle command can repair an ordinary binary upgrade; moving/uninstalling an arbitrary manually installed binary is not promised transparent recovery.

Use production label `com.adevcontainer.git-credentials`, plist `~/Library/LaunchAgents/com.adevcontainer.git-credentials.plist`, nonsecret registry under `~/Library/Application Support/adevcontainer/git-credentials/`, and lock/control endpoint under owner-private `~/.adevcontainer/git-broker/`. Validate Unix-socket path length before creation; do not truncate identifiers or fall back to a public endpoint. Tests substitute a `com.adevcontainer.git-credentials.test.<UUID>` label and exclusively temporary paths through an internal launch-context value; no production plist is overwritten.

Persist only nonsecret registrations: runtime incarnation/context, connection user, source provenance, authorized destination set, protocol version, and an ephemeral-override-required bit. Preserve no tokens or rejection values on disk. Read the actual managed container's identity, state, `configuration.creationDate`, and platform from machine JSON before reconnecting. Apple [ContainerConfiguration](https://github.com/apple/container/blob/main/Sources/ContainerResource/Container/ContainerConfiguration.swift) defines creationDate/platform; use an optional credential-context parser so older non-credential runtime paths do not acquire new prerequisites. A missing/invalid incarnation fails closed for unattended recovery rather than treating a reusable name/config hash as an incarnation. Fixtures and real smoke verify the runtime shape before enabling delivery. A new service generation and fresh relay handshake fence pending requests even for a valid same-container restart.

Keep the broker idle when no containers are connected; no idle-shutdown policy is needed. Reconcile runtime state at a finite interval, reconnect live containers with bounded backoff, and invalidate stopped/deleted or identity-mismatched registrations. Recovery checks use runtime metadata, not credential polling. Stop/delete/purge and failed-clone cleanup explicitly unregister their sessions; process loss is also handled by EOF/deadlines. Rebuild establishes a new incarnation/generation before any hook can obtain a credential.

## Flow

```text
up/clone/start/rebuild/reuse/refresh
    -> private same-user broker registration
    -> runtime boundary opens container exec -i (no TTY)
    -> native guest relay owns a connection-user-private Unix socket

Git get/store/erase -> helper/native client -> guest socket -> relay stdout
    -> broker validates established session + destination + request
    -> existing host credential provider (get only, bounded/noninteractive)
    -> exec stdin -> relay -> matching client -> Git credential response
```

Add a long-lived duplex-process abstraction rather than reusing buffered ProcessResult or StatusPrinter tee. Drain both streams, never tee raw relay/provider payloads or errors into logs. Use a simple versioned length-prefixed binary frame with a fixed header (operation, request ID, generation, payload length) and length-delimited credential fields; this avoids a C JSON dependency. Reject oversized/truncated/duplicate/conflicting fields and newline/NUL injection before provider input construction. Correlate per-generation IDs; disconnect cancels all pending waiters; late responses cannot satisfy another operation. Do not replay timed-out gets after reconnect. Bound queue size and provider concurrency, using fair admission across sessions; only equivalent acquisition contexts may share simultaneous provider work.

Start with internal defaults: 15-second end-to-end helper deadline, 30-second lifecycle-setup deadline, 30-second rejection cooldown, 64-KiB frames, eight active provider jobs, and 64 queued jobs. Use monotonic injected clocks and finite reconnect/backoff/reconciliation intervals. These are implementation defaults, not user-facing flags. Provider descendants must be terminated/reaped when their deadline expires; merely canceling a waiter is insufficient. Asynchronous pipe drainage/cancellation remain outside domain policy.

Store discards input without approve/persistence. Erase compares against bounded recent delivery records keyed by session and acquisition scope, then records a keyed in-memory fingerprint. A delayed erase cannot invalidate a newer different credential, and an unknown/uncorrelatable rejection cannot erase a host credential. During cooldown suppress the same rejected value, not a different replacement; expiration or explicit refresh permits another attempt, even if the provider still returns the same value. No internal retry loop and no persistent blacklist are needed.

## Architectural boundaries
`GitCredentialBrokerPolicy` owns destination validation, rejection state, bounds, and generation/correlation policy without launchd/process/runtime imports. A separate broker orchestrator coordinates policy, a provider port, transport events, and the nonsecret registry. `GitCredentialBrokerService` owns launchd/control-IPC/locking and launches internal mode through the CLI entry; `GitCredentialConnection` prepares/migrates the guest and registers lifecycles. Runtime adapters alone invoke Apple container. Existing discovery, connection-user resolution, URL parsing/redaction, and provider precedence remain shared, not copied into commands.

Registration authorizes only the discovered normalized scheme/host/port set. Preserve sibling paths and queried-username response compatibility without allowing a guest username to select another host account. Preserve legacy HTTP exactly where discovered: HTTP/HTTPS do not authorize one another, and no provider unsafe-HTTP setting is enabled. Pass actual validated Azure query paths; do not send pathless GCM calls or substitute the original repository when a sibling is queried. Scheme/port normalization must survive discovery and provider input, including explicit nondefault ports; keep normalized hostname distinct from Git's host-with-port field so Azure recognition does not break. This limits acquisition requests, not the privileges of a delivered bearer token.

## Migration and rollback
Replace the product-owned seed helper idempotently; remove identified product-owned seeded credential files without reading/logging them. Preserve existing global helpers and their order. Retain Azure URL-scoped helper installation exactly once, remove old empty resets, and keep useHttpPath. Use the HTTPS-scoped keys for HTTPS and equivalent HTTP-scoped keys only when legacy HTTP Azure was actually discovered; otherwise Git can omit the organization path for HTTP and accidentally produce a pathless GCM request. Earlier helpers may answer first; successful Git authentication is not evidence of broker use. Tests isolate the helper chain and assert provider invocation.

Legacy non-Azure clone's generic credential.helper store has no reliable entry provenance. Do not erase its file or unrelated user entries to manufacture a no-cache test. Preserve unidentified legacy configuration/data and document that these earlier answers are outside automatic freshness. New HTTP(S) clone prepares the automatic helper before populate/hooks, creates no store/approve path, and allows anonymous public clone when the provider misses. Never replay a legacy product seed on broker failure. Downgrading may reintroduce the older release's behavior; byte-for-byte credential/cache rollback is not promised.

## Security considerations
The boundary is the host-established container session and resolved connection user; guest root can exercise that authority. Validate all guest messages, original identity, exact destination context, URL fields, and socket ownership before provider execution. Never expose the host control socket/runtime endpoints or execute guest-supplied command/config text. Socket cleanup uses validated private directories, lstat/no-follow checks, and only known owned endpoints; it must not delete arbitrary user paths.

launchd does not inherit each invoking CLI's environment. Register explicit host token overrides through private IPC into session memory, not plist/argv/child environment. Persist only a needs-reregistration indicator; after broker restart such sessions fail closed until re-registered, rather than silently switching accounts/providers. Disable Git prompts and GCM GUI/TTY prompts; keep all provider output secret-safe. Real authentication, reject/erase/logout, or shared-cache manipulation is not part of automated tests.

## Isolated smoke verification
Add a test harness using an internal dependency-injected launch context: a unique test job label, private state/socket/log roots under the approved temporary directory, an absolute development executable, synthetic providers, and exclusively created throwaway containers. This is not a public option/environment-based alternate service mode. Unit tests cover normal command integration; real smoke exercises supervision/exec/installed static relay through the same library adapters without registering the production job. Do not rely on changing HOME or overwriting the user's existing LaunchAgent to achieve isolation.

For the separate launchd broker process, provide synthetic acquisition through the existing Git provider, not a new production provider: a test-owned Git configuration selects only a local fixture credential helper for `https://credential-smoke.invalid`. The internal test launch context supplies a sanitized provider environment with system/user Git config excluded, command-level inherited config cleared, explicit real-token overrides excluded, tracing disabled, and prompts disabled. No user credential store/config/gh fallback or network authentication is involved. Guest Git exercises `credential fill/reject` only against this isolated helper chain; reject reaches the guest erase operation, never host reject. Entry dispatch tests build the CLI explicitly and use invalid/isolated contexts, while fake-library tests cover service behavior before authorized real smoke.

The test executable, not the product CLI, may select its deterministic credential aggregate with `ADEVCONTAINER_CREDENTIAL_TESTS_ONLY=1`; a separate test-only `ADEVCONTAINER_CREDENTIAL_SMOKE=1` opt-in runs the previously authorized isolated smoke. Mock-runtime command tests inject fake broker/provider dependencies and fail if they accidentally select a real launchctl adapter. These test gates introduce no public product options and are never interpreted by the production broker to redirect its registry.

Capture nonsecret baseline existence/hashes of production job/plist/state, without dumping credential-related contents. On success, injected failure, and handled signals: stop accepting requests, bootout only the unique test service, reap relay/exec processes, remove only test-created containers/endpoints/state, and verify absence plus unchanged production baseline. Never stop plantsuite or another pre-existing container for smoke. SIGKILL cannot run a trap: print/preserve a secret-free test-owned cleanup manifest and a targeted cleanup procedure for a later operator/harness sweep; do not claim guaranteed cleanup after an unhandleable crash. Real providers require separate authorization, and neither synthetic success nor unchanged tokens proves OAuth renewal.

The supplied prior spike demonstrated 66-second duplex, out-of-order concurrency across restart, interrupted pending requests, and two Azure HTTPS lookups. Its reconnection/fencing were harness behavior; stale sockets survived restart and Python supplied the relay. Product behavior with the shipped native helper still requires verification.
