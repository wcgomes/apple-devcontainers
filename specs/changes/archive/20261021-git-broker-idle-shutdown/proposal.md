# Proposal: Bound Git broker lifetime to managed credential sessions

Archived on 2026-10-21 after explicit user confirmation and coordinator-confirmed independent approval. The three added requirements and eleven scenarios are consolidated in [core.md](../../../core.md); execution and review evidence remain in [tasks.md](tasks.md).

## Intent
The per-user Git credential broker currently runs indefinitely, including after its last container stops and on later logins. Retain automatic connection setup and crash recovery without leaving an idle broker permanently running.

## Scope
Add a bounded lifetime contract to the core Git credential requirements. Cover first-session activation before clone/hooks, last-session retirement, external stop/removal, registration/shutdown races, rapid restart, and launchd crash supervision. Preserve the realized core and clone contracts except for this explicit lifetime refinement; the archived automatic-git-credentials bundle is immutable.

## Non-goals
No refresh-credentials command, public grace/recheck flags, new dependencies or daemon, provider renewal changes, real credential access, production service mutation, or monitoring of unrelated Mac containers. No changes to token override, rejection cooldown, helper ordering, workspace/volume cleanup, or existing warning-only setup behavior. No automatic discovery/adoption of containers that have no credential registration.

## Approach
Keep the existing installed binary, private registry/control socket, launchd adapter, and lifecycle setup sites. Distinguish a dormant loaded job from a running broker, make successful idle exit non-restarting, and explicitly activate a dormant job for new registration. Base idleness on registered/in-progress demand, not on time since the last Git lookup or whether a relay is currently connected. Revalidate before atomically committing to retirement; a registration crossing that boundary must reconnect/reactivate within its existing deadline.

## Decision index
- **Timing:** use an internal 5-second continuous zero-demand grace and a maximum 2-second recheck cadence while probes/control handling are responsive. This retains the current reconciliation rhythm, absorbs rapid stop/start, and removes an idle process in at most 7 seconds under healthy local conditions; it is deliberately independent of the 30-second rejection cooldown.
- **Unknown is not stopped:** runtime transport failure, timeout, invalid machine output, or an ambiguous inspect failure cannot prove a container stopped. Preserve the nonsecret registration and defer idle retirement while its state is unknown; suspend unsafe delivery/reconnect until identity is validated. Definitive machine-readable stopped/absent/replaced state permits invalidation. Runtime work remains deadline-bounded; no healthy-runtime retirement guarantee is claimed during an outage.
- **Ownership and races:** make the final empty-state decision and registration admission share a serialized state boundary; retain the existing singleton lock through endpoint cleanup. Requests not admitted before retirement retry activation against the successor, never succeed against a retiring instance. Avoid waiting for runtime calls or activation locks while holding broker state locks.
- **Supervision:** normal idle exit is success; conditional launchd failure restart replaces unconditional KeepAlive. A loaded dormant job is explicitly started without killing a healthy broker. RunAtLoad may perform one bounded reconciliation at login/bootstrap, but an empty registry must end in dormant state rather than restart forever. SIGTERM/SIGINT cleanup retains existing intentional-stop semantics; abnormal process death remains recoverable.
- **Compatibility:** provisioning and registration still finish before HTTP(S) populate/hooks when setup succeeds, healthy reuse does not poll providers or duplicate sessions, unregister does not activate a stopped broker, and explicit token overrides are not recovered from disk after a crash.
- **Resumable migration:** on-disk target bytes alone do not prove the loaded job was upgraded. A private, nonsecret `loaded-definition.plist` receipt is invalidated durably before migration and atomically committed only after successful bootstrap; missing/mismatched confirmation forces safe replacement even when disk already matches. Bootout precedes target-plist replacement, failures remain failures, and confirmed healthy registrations only kickstart idempotently rather than reload every time.
- **Verification isolation:** add a test-executable-only probe using the production service loop/launchd adapter with synthetic runtime ports. A separately authorized opt-in real-launchd test can exercise PID/restart behavior without containers, network, host Git providers, or production paths. Keep the existing credential smoke safety gate intact.
- **Artifact routing:** no design.md is needed: concise decisions here and ordered tasks cover the bounded lifecycle flow. No overlapping active change exists; the earlier automatic-git-credentials bundle is archived. Archive-time integration will add this contract to core.md, not rewrite history.

Pre-change source validation: GitCredentialBrokerService emitted RunAtLoad=true/KeepAlive=true; GitCredentialControl ran until an external signal and reconciled every two seconds; unregister removed only one registration. GitCredentialBroker.reconcile treated all context failures as absence, requiring correction before idle exit; the runtime context adapter also conflated failed inspect with invalid context. Wiki credential-seeding text is stale relative to source and the realized automatic-connection contract; it is descriptive only and is not edited here. CodeGraph was attempted first, but its CLI is unavailable and no MCP explore tool is exposed; targeted source inspection was used instead.
